# poseidon-rust

[![Rust tests](https://github.com/mdvillagra/poseidon-rust/actions/workflows/rust.yml/badge.svg)](https://github.com/mdvillagra/poseidon-rust/actions/workflows/rust.yml)

Rust implementation of the [Poseidon hash function](https://eprint.iacr.org/2019/458) over arkworks prime fields.

This repository is intended as a compact research and learning implementation: the permutation, sponge absorb/squeeze flow, parameter loading, and unit tests are visible in a small codebase.

## What this implements

- Poseidon permutation with add-round-key, S-box, and MDS linear layers.
- Sponge-style `hash` function with caller-provided rate and output length.
- BLS12-381 scalar-field parameter file for `n=255`, `t=5`, `alpha=5`, `M=128`, `R_F=8`, `R_P=56`.
- Round constants and MDS matrix generated with the Grain LFSR approach used by the HadesHash reference implementation.
- Unit tests for parameter loading, padding, the ARK step, and a deterministic digest regression vector.

## Installation

Use this repository as a Git dependency:

```toml
[dependencies]
poseidon-rust = { git = "https://github.com/mdvillagra/poseidon-rust" }
```

The library crate exposed by `Cargo.toml` is named `poseidon_lib`.

For local development:

```bash
git clone https://github.com/mdvillagra/poseidon-rust.git
cd poseidon-rust
cargo test
```

## Quick example

```rust
use ark_bls12_381::Fr;
use poseidon_lib::{
    hash,
    read_constants::read_constants_bls12381_Fr_n255_t5_alpha5_M128_RF8_RP56,
};

let constants = read_constants_bls12381_Fr_n255_t5_alpha5_M128_RF8_RP56();
let input = vec![Fr::from(1_u64), Fr::from(2_u64), Fr::from(3_u64)];

// output_length = 1, rate = 3
let digest = hash(&input, &constants, 1, 3);
assert_eq!(digest.len(), 1);
assert_eq!(
    digest[0].to_string(),
    "35749691652817681892908057964048881583928194394669750191375048829827770765536",
);
```

## API surface

| Function | Purpose |
| --- | --- |
| `hash(input, constants, output_length, r)` | Sponge-style hash over a vector of field elements. |
| `poseidon_permutation(state, constants)` | In-place Poseidon permutation over a mutable state. |
| `read_constants_bls12381_Fr_n255_t5_alpha5_M128_RF8_RP56()` | Loads the committed BLS12-381 scalar-field constants. |

## Parameters

The committed parameter file is:

```text
poseidon_params_Frbls12381_n255_t5_alpha5_M128.txt
```

| Parameter | Value |
| --- | --- |
| Field | BLS12-381 scalar field |
| State width `t` | 5 |
| S-box exponent `alpha` | 5 |
| Security target `M` | 128 |
| Full rounds `R_F` | 8 |
| Partial rounds `R_P` | 56 |
| Round constants | 320 |

The constants and MDS matrix follow the output format of the HadesHash Poseidon parameter-generation script.

## Tests and regression vectors

Run the test suite with:

```bash
cargo test
```

Current tests cover:

- committed parameter-file dimensions;
- padding to the sponge rate;
- add-round-key behavior;
- deterministic digest for `[1, 2, 3]` over the committed BLS12-381 scalar-field parameters.

The digest regression vector is:

```text
hash([1, 2, 3], output_length = 1, rate = 3)
= 35749691652817681892908057964048881583928194394669750191375048829827770765536
```

This vector is useful for catching accidental implementation changes. It should not be treated as an independent conformance suite.

## Running the demo binary

```bash
cargo run
```

`cargo run` prints a sample hash output and field moduli for BLS12-381 and BLS12-377.

## Security notes

- This is not an audited cryptographic library.
- The regression vector above was generated by this implementation, not by an independent reference implementation.
- Production use should compare outputs against independent Poseidon test vectors for the exact field, width, S-box exponent, round counts, padding, and domain-separation convention required.
- The current sponge padding appends zero field elements until the input length is a multiple of the rate. Protocols requiring domain separation should define and test their own input encoding.

## Limitations

- Only one committed parameter file is wired into the public loader today: BLS12-381 scalar field, `t = 5`, `alpha = 5`.
- The implementation prioritizes readability over constant-time hardening, allocation minimization, and production API ergonomics.
- There are no independent cross-library conformance vectors checked into this repository yet.

## Relation to poseidon-benchmarks

[`poseidon-benchmarks`](https://github.com/mdvillagra/poseidon-benchmarks) is the companion benchmarking repository. It compares several Rust Poseidon implementations used in ZK-adjacent systems and records Criterion reports. This repository is a compact implementation; the benchmark repository is the comparative performance study.
